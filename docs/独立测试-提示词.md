# 独立测试 Agent 会话提示词（B100）

用途：换一个**全新会话**（不携带开发上下文），把第二节整段贴进去，即可完成"独立测试 Agent 编写/补充测试"这一过程项。测试 Agent **只写测试、不改业务代码**，与开发会话上下文互相独立。

## 一、测试前准备（在旧环境执行一次即可）

```powershell
cd D:\Desktop\questions-main
$env:GATEWAY_PORT="18080"; docker compose -f docker-compose.trade.yml up -d --build
# 本地 MySQL/Mongo 可用时 repo 直测才会真正执行：
$env:TRADE_REQUIRE_DB="1"
```

## 二、贴给新会话的提示词

```
你是独立测试 Agent。仓库：D:\Desktop\questions-main（分支 dev/1）。
原始题面：docs/题目01-业务实现.md 第 1 节（先读原始验收条件 S1-S6 与 E01-E18，再读代码）。

任务：在阅读原始题面与最终版本代码之后，独立编写或补充测试，禁止修改任何业务代码（internal/、cmd/、scripts/ 的生产文件），只允许新增/修改 *_test.go 与测试辅助。

必须覆盖：
1. 你认为题面要求但现有测试未覆盖的边界（至少 3 条，说明为什么漏了）；
2. 对你怀疑有缺陷的路径先写失败测试再给结论（禁止只看代码下结论）；
3. 网关 HTTP 层（internal/gateway/handler、router）：鉴权、越权、参数校验、下游错误映射。

输出：
- 新增/修改的测试清单（文件 + 测试名 + 覆盖的题面条目）；
- 运行证据：go test -count=1 ./internal/... ./pkg/middleware/...（TRADE_REQUIRE_DB=1）完整输出；
- 缺陷报告（如有）：每条含复现步骤、期望/实际、严重级别；
- 明确声明：本会话为独立测试会话，未读取开发会话历史。
```

## 三、完成后回填

把测试 Agent 的输出存为 `docs/独立测试记录.md`，并在 `docs/验收报告-题目01.md` 整改记录中把 B100 项的会话编号补上。

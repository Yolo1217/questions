## 2. 回退演练（2026-11-12 实测，A4-07）

撤销方式：`git checkout <上一版本>` 重新构建镜像并冒烟——因为服务为无状态容器 + 数据卷，回退只需回滚镜像，不回滚数据库。

| 步骤 | 命令 | 结果 |
|---|---|---|
| 1. 检出上一版本 | `git checkout 2f34536`（整改后、本次发布前最后可运行版本） | OK |
| 2. 重建容器栈 | `docker compose -f docker-compose.trade.yml up -d --build` | OK |
| 3. 冒烟 | `bash scripts/smoke-http.sh`（容器网络内） | **全部通过（25 项）** |
| 4. 恢复发布候选 | `git checkout dev/1` → `up -d --build` → 冒烟 | **全部通过（25 项）** |
| 5. 还原环境 | `docker compose ... down` | OK |

结论：任一历史版本可在约 2 分钟内用同一 compose 编排恢复并通过全部冒烟，回退路径可用。

## 3. 正式回退预案（上线后异常时执行）

```powershell
# 1) 冻结入口（可选）：网关容器停止接收流量
docker compose -f docker-compose.trade.yml stop gateway

# 2) 回滚代码与镜像到上一 tag
git fetch --tags
git checkout v1.0.0            # 或上一个已知良好的 tag/提交
docker compose -f docker-compose.trade.yml up -d --build

# 3) 冒烟确认
docker run --rm --network questions-main_default -v "${PWD}:/work" -w /work `
  -e BASE_URL=http://gateway:8080 alpine:3.22 `
  sh -c "apk add --no-cache bash curl jq openssl && bash scripts/smoke-http.sh"

# 4) 数据不回滚：台账与异常表为追加写，新版本向前兼容；确认后再放开 gateway
docker compose -f docker-compose.trade.yml start gateway
```

注意：数据库仅做追加写入（台账/异常表），版本回滚不删数据；若新版本引入了不可逆 schema 变更，需先在测试库演练迁移回滚后再上线。

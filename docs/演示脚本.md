# 演示/讲解视频脚本（5 分钟，题目01）

录屏建议：OBS / Windows Win+G，先跑 `scripts/seed-demo.ps1` 播种六状态 + 三异常演示数据，全程对着真实系统操作，不剪不快进（讲清优先）。

## 0. 开场（30 秒）

- 一句话：小型电商订单交易系统，重点解决四个硬问题——并发超卖、支付回调幂等与验签、售前退款与发货竞争、异常支付闭环。
- 打开 `http://localhost:18080/` 总览页：展示 5 个工作台入口 + 预置账号。

## 1. 买家侧：下单与支付（60 秒）

1. `/buyer.html` 用 `buyer1` 登录，选 P1 下单 → 状态 CREATED、库存 -1（预占）。
2. 点「模拟支付」→ PAID，台账出现"支付成功入账（预占转实扣）"。
3. **同流水号再推一次**（幂等演示）→ 提示重复通知，台账条数不变。
4. 讲一句：支付回调是 HMAC-SHA256 验签 + `channel_trade_no` 幂等 + 条件更新三道防线，验签先于落库，伪造流量只落异常表。

## 2. 仓库与竞争场景（60 秒）

1. `/warehouse.html` 用 `warehouse01` 登录，对 PAID 订单登记承运方/运单号 → SHIPPED。
2. 回买家页对另一单申请退款 → REFUNDING；仓库页对它点发货 → 被拒 `order_refunding`（竞争拦截演示）。
3. 讲一句：退款与发货在同一把状态锁上，条件更新保证只有一个能赢。

## 3. 客服退款闭环（60 秒）

1. `/refund.html` 用 `support01` 登录，同意退款 → 首次渠道失败（设计内路径，REFUNDING）。
2. 再点一次 → REFUNDED，库存回补。
3. 对同一单再提交 → `duplicate=true` 幂等提示。
4. 驳回路径：驳回必须填原因，空原因被拒。

## 4. 异常闭环（60 秒）

1. `/exception.html`：展示三类异常——验签失败 / 金额不符 / 无主支付（seed 造好）。
2. 处置一个：refund / verify / ignore，必填原因，闭环后不可再改。
3. 按渠道流水号反查回调结果；讲一句：伪造签名不落回调表、不占流水号，真实重试不受影响（评分整改后的语义）。

## 5. 运营核查 + 质量证据（60 秒）

1. `/ops.html` 用 `ops01` 登录：已收款/已退款/可售/预占/待处理异常五指标，与台账对得上。
2. 越权演示：买家 token 访问运营接口 → `permission_denied`；匿名 POST `/api/v1/orders` → 401。
3. 切终端：`go test -count=1 ./internal/order/...`（TRADE_REQUIRE_DB=1）全绿；覆盖率 91.0%。
4. 展示 GitHub Actions：最近 run 全绿（gofmt/vet/单测/覆盖率门禁 + 容器部署冒烟 25 项）。

## 收尾（10 秒）

- 交付物一句话：仓库（分支 `dev/1`）、验收报告、独立复验记录、CI 门禁、一键部署与冒烟脚本、演示数据播种脚本。

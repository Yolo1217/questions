# 独立复验会话提示词（D4）

用途：换一个新会话（不携带开发上下文），把下面整段贴进去即可完成 D4 复验。复验者**只复核、不改代码**。

## 一、复验前准备（在旧环境执行一次即可）

```powershell
cd D:\Desktop\questions-main
# 方式A：本机三进程
go run ./cmd/user          # 终端1
go run ./cmd/order         # 终端2
go run ./cmd/gateway       # 终端3（占用 8080，需先释放该端口）
# 方式B：容器化（推荐，自带 MySQL，不占 8080）
$env:GATEWAY_PORT="18080"; docker compose -f docker-compose.trade.yml up -d --build
```

## 二、贴给新会话的提示词

```
你是独立复验人。仓库：D:\Desktop\questions-main（分支 dev/1）。

任务：按 docs/验收报告-题目01.md 复核题目01（电商订单交易）是否达标，只做验证与取证，禁止修改任何代码、配置、测试。

复核范围仅三项：
1. 红线 7 条（报告第 1 节）逐条给出「触发/未触发」+ 证据来源（测试名或命令输出）。
2. 运行 scripts/smoke-http.sh（Linux/macOS/容器内）或 scripts/smoke-pages.ps1（Windows），记录完整输出与通过项数；若环境起不来，如实记为「无法复验」并说明原因，不要推测通过。
3. 独立抽查两条关键码路径，确认报告结论非编造：
   - internal/order/service：支付回调是否验签在前、幂等在前，异常分支是否只落异常表不改订单状态；
   - internal/order/service：发货是否显式拒绝 CLOSED/REFUNDED/REFUNDING 并写台账。
   给出文件路径 + 关键行号 + 一句话说明。

输出格式：Markdown 表格（编号/结论/证据），末尾给一行总裁定：PASS 或 FAIL + 未通过项编号。
不得引用本会话之外的任何结论；所有 PASS 必须有本次实际命令输出或代码行号支撑。

环境说明：MySQL root:root@127.0.0.1:3306（测试库自动创建 questions_test*）、Mongo 127.0.0.1:27017（容器 questions-mongo）。测试命令：go test -count=1 ./internal/order/... ./pkg/middleware/...，需要强制库校验时加 TRADE_REQUIRE_DB=1。
```

## 三、复验产出如何回填

把新会话的结论表追加到 `docs/验收报告-题目01.md` 末尾（新增“## 7. 独立复验记录”），同时把 D4 行改为「已完成」、结论区更新为最终裁定。若复验发现新问题，走 `fix` 提交并保留复验输出。

## 四、常见失败点（复验者请先排除）

| 现象 | 原因 | 处理 |
|---|---|---|
| 8080 被占用 | 本机其他容器/服务占用 | 用 composer 方式并设 GATEWAY_PORT=18080 |
| 登录返回 `invalid_request` | 请求体不是 UTF-8 JSON（Windows PowerShell 单引号转义） | 用 `scripts/smoke-*.ps1` 或 `curl.exe -d @file` |
| 测试瞬间“通过”但没跑用例 | 数据库不可达时 TestMain 静默跳过 | 设 `TRADE_REQUIRE_DB=1` 强制失败 |
| 容器 user 服务退出 | MySQL 建库期探活误报 | 用仓库内 compose（已改真实查询探活 + restart: on-failure） |

# Order State Machine（订单状态机）

## Overview

本技能提供一套小型交易系统的订单生命周期标准：固定的状态集合、唯一的合法迁移入口表，以及基于该表的订单主流程设计、实现与状态类 bug 排查方法。核心原则：**状态迁移表是唯一合法入口，表以外的任何迁移一律视为非法，必须拒绝并记录。**

## 适用场景

- 设计与实现小型交易系统的订单生命周期
- 排查"已退款还能发货""关单又被改回已支付""仓库看到不该发的单""状态字段互相打架"
- 为买家 / 仓库 / 客服 / 运营提供同一份订单状态的不同视图

## 状态定义（最小集，禁止随意扩展）

| 状态码 | 名称 | 含义 | 是否终态 |
|---|---|---|---|
| CREATED | 待支付 | 已创建未支付，库存为预占 | 否 |
| PAID | 已支付 | 支付成功，预占转为实扣 | 否 |
| SHIPPED | 已发货 | 仓库已出库 | 否 |
| COMPLETED | 已完成 | 确认收货 / 自动完成 | 是 |
| CLOSED | 已关闭 | 未支付超时或买家取消 | 是 |
| REFUNDING | 退款中 | 退款已受理未完成 | 否 |
| REFUNDED | 已退款 | 退款成功，库存回补 | 是 |
| EXCEPTION | 异常待处理 | 无法自动判定的冲突，等人处理 | 否 |

## 状态迁移表（唯一合法入口）

| 事件 | from | to | 必要副作用 |
|---|---|---|---|
| 下单 | 无 | CREATED | 预占库存，写库存预占流水 |
| 支付成功 | CREATED | PAID | 预占转实扣，写支付流水 |
| 支付成功 | CLOSED / REFUNDED / COMPLETED | EXCEPTION | 记录迟到通知，生成客服工单 |
| 超时 / 买家取消 | CREATED | CLOSED | 释放预占库存 |
| 仓库发货 | PAID | SHIPPED | 写物流单号 |
| 仓库发货 | REFUNDING / REFUNDED | 拒绝并转 EXCEPTION | 不产生物流单 |
| 退款受理 | PAID / SHIPPED | REFUNDING | 冻结发货，写退款单 |
| 退款成功 | REFUNDING | REFUNDED | 回补库存，写退款流水 |
| 确认收货 | SHIPPED | COMPLETED | 结算 |

## 工作方式

### 设计与实现订单主流程

1. 以上述状态定义和迁移表为准绳，不得随意新增状态或迁移；确有业务诉求时先提示用户该迁移不在表内，经确认后由用户显式扩展。
2. 实现时将迁移表落为单一入口：所有状态变更必须经过同一个状态变更入口（如统一的状态机函数 / 单条 UPDATE 语句），UPDATE 条件必须包含当前状态（乐观迁移，如 `UPDATE orders SET status = 'SHIPPED' WHERE id = ? AND status = 'PAID'`），受影响行数为 0 即判定迁移失败。
3. 迁移与必要副作用放在同一事务内完成；副作用（预占 / 实扣 / 释放库存、各类流水、退款单、客服工单）不可遗漏。
4. 对已处于终态（COMPLETED / CLOSED / REFUNDED）的订单，正常业务事件不得再改写状态，仅允许按迁移表转入 EXCEPTION。
5. 超时关单作为 CREATED → CLOSED 的定时触发事件实现，与支付成功回调并发时依赖状态条件更新保证只有一个结果生效。

### 排查状态类 bug

1. 先确认订单当前状态与触发事件，对照迁移表判断该次变更是否合法：
   - 不在表中的 (from, 事件) 组合 → 非法迁移被放行，检查状态变更入口是否绕过了条件更新或缺少 from 校验。
   - 合法迁移但副作用缺失 → 检查迁移与副作用是否在同一事务。
2. 常见问题定位：
   - "已退款还能发货" → 发货入口未拒绝 REFUNDING / REFUNDED，缺少"拒绝并转 EXCEPTION"分支。
   - "关单又被改回已支付" → 迟到的支付通知直接改写了 CLOSED，未走 CLOSED → EXCEPTION 分支。
   - "仓库看到不该发的单" → 仓库视图未过滤 REFUNDING / 已终态的订单，属于视图投影问题而非状态错误。
   - "状态字段互相打架" → 存在多个入口各自改写状态，未收敛到唯一迁移入口。
3. 修复方案以"收敛到唯一迁移入口 + 条件更新 + 事务内副作用 + 非法迁移拒绝并记录"为准。

### 多角色视图

状态本身只有一份，不同角色看到的是同一状态的投影：

- 买家视图：展示 CREATED/PAID/SHIPPED/COMPLETED/CLOSED/REFUNDING/REFUNDED 的用户可读名称。
- 仓库视图：只应看到可发货订单（PAID 待发货、SHIPPED 已发货），REFUNDING 及终态订单不出库。
- 客服视图：可见全部状态，重点关注 EXCEPTION 待处理单。
- 运营视图：基于各状态订单数做统计，不修改状态。

实现视图时禁止为角色单独维护状态字段或副本数据，一律从同一个订单状态推导。

## 硬性规则

- 状态集合为最小集，禁止随意扩展。
- 迁移表以外的任何迁移一律非法：必须拒绝执行，并记录（日志 / 流水）以供排查。
- 无法自动判定的冲突一律转 EXCEPTION，交由人工处理，不得自动猜测结果。
